# BitcoinTX 2.0: the docs overhaul

The plan for bringing every document, and the app's own help, up to date
with 2.0 (#667, part of #251). Planning only: no document is rewritten
by this file. B9 (#654) took "one wallet, one exchange" out of every text
in this repository, and `test_texts_2_0_357.py` keeps it out. This
overhaul goes further: each document is read again against what 2.0
does, describes every 2.0 feature its reader needs, and keeps nothing
that is no longer true. This file is deleted once its last step is done
(D7b and D8 come with 2.0's release: `docs/temp/README.md`).

**In plain words:** 2.0 isn't the small, one-wallet tracker 1.x was, and
the documents still read in places as if it were: they call BitcoinTX
"minimalist", the landing page offers "one wallet, one exchange", and
some of 2.0's features (the "Sales by exchange" table, going back to 1.x,
the old AI connector's refusal) aren't in the README and the user guide.
The overhaul keeps the documents as thorough as they are, adds every 2.0
feature where its readers look, takes out everything no longer true, and
makes every copy of a fact agree. What testers read is done before the
beta; the developer documents follow in the release window.

## 2. What the owner asked

The owner's request (2026-10-24, to the build's lead): "did you factor in
all the Docs changes we will need with this release including getting
rid of one exchange and one wallet verbage everywhere as well as
minimalist. ... It will be an overhaul of the docs wouldn't you say".
#667 first read "minimalist" as a style for the documents. The owner
corrected that the same day, in this planning session: "my point was we
need to remove minimalist concept from the docs because now we are not
minimalist", and, asked how far the overhaul goes, chose to rethink each
document: "my point was not to make the docs overly concise ... we want
very thorough docs like we had just revised to reflect all the features
of 2.0 and removing anything that is no longer true like minimalist, 1
account, 1 exchange, etc".

So the rules for every step:

1. **Thorough.** Each document keeps its depth. Nothing true and useful
   is cut to make a page shorter; no length goals.
2. **Every 2.0 feature, where its reader looks** (3.2): the user guide
   explains each one fully, the README presents each one, the StartOS
   instructions and the connector's documents cover what their readers
   do.
3. **Nothing that is no longer true** (3.3): no "minimalist", no "one
   wallet", "one exchange" or "one account" outside a sentence about 1.x,
   no out-of-date version, count, path or screen name. Each statement is
   checked against 2.0's code, not against another document.
4. **Every copy agrees.** A fact may be in each document whose reader
   needs it; the full explanation has one home (3.4), and every other
   copy says the same thing and, where it is shorter, links to it. A
   copy is corrected, never cut down to a pointer (StartOS's documents
   follow Start9's own rule, 4.1).
5. **Each document for its reader.** A procedure lives where its reader
   looks: the way back to 1.x moves from the maintainer's guide to the
   README.
6. As always: plain words, the app's screen names as the screen shows
   them, "multiple wallets, exchanges or accounts" never "several", no
   personal data.

## 4. Constraints

### 4.1 Start9's guide

Start9's rules win for what they govern (AGENTS.md, "Start9"): `startos/`,
and which pages `instructions.md`'s Documentation names. Read on
`live-docs` at a899b089 (2026-10-23), in
`start-technologies/projects/start-sdk/docs/src/`:

- **`writing-instructions.md`:** `instructions.md` is for the person
  running the service, from first launch to use, in the second person.
  It doesn't restate the store listing, has no install steps, no
  versions, nothing on what an update changed, and no Limitations section
  unless something would really surprise. Upstream behaviour (here, the
  app's own features) is "Linked from the Documentation section; never
  duplicated". Its Documentation bullets are `- [Title](URL) — a few
  words`; a GitHub `blob/…/x.md` link fetches that one page; "Leave out
  docs that don't apply to the package". So the README, which holds the
  other platforms' install steps, is never one of them, and USING stays
  free of install steps.
- **`writing-readmes.md`:** `startos/README.md` keeps its fixed headings,
  verbatim and in order: the table of contents, eleven sections and the
  quick reference, thirteen H2s in all; each opens with prose; no
  version numbers; "Do not duplicate upstream documentation", "State
  differences, never sameness", "Do not restate `instructions.md`"; no
  links to upstream documentation. So 2.0's features go into
  StartOS's documents only where StartOS changes them; their full
  description is USING's.
- **`project-structure.md`, "AGENTS.md and CLAUDE.md":**
  `startos/AGENTS.md` holds only what is specific to the package and
  restates neither of the other two; a prohibition stays inline.
- **`versions.md`, "Release Notes":** the release notes are "the only home
  for what an update asks of the user". The way back to 1.x reaches a
  StartOS user there, never in `instructions.md`.
- **`manifest.md`, "How long each one may be":** short at most 120
  characters (about 80 show), long at most 2,000, in every locale.
